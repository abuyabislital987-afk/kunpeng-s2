# 给 Agent 的启动提示词

复制下面内容，替换方括号中的任务信息即可。Agent 应持续完成本轮候选与验证，不需要逐步等待确认。

```text
请在这个仓库优化 [conv / zgemm / trsm]。本轮候选 ID 是 [C1-alice]，父版本是 [C0]，我要探索的方向是 [填写方向；没有明确方向时请你先根据已有证据选择]。

先读 AGENTS.md、docs/BASELINES.md、docs/PLAYBOOK.md 和已有实验记录。检查当前工作区，保留其他人的改动。如果父版本只有历史证据，先按 README 无 parent 创建 C0/Z0/T0，保持代码不变，完成当前环境三轮测试、record、promote，建立基线后再创建子候选。使用独立分支，只改候选 source 目录。

根据源码、实测硬件信息和既有失败记录提出一个可检验的优化假设，说明为什么值得测试，完成实现。保持官方 benchmark、输入、计时、参考实现、精度要求和线程上限不变。修改 run.sh 必须复核实际编译 flags、线程、绑定和验证逻辑；优化参数固化到候选 run.sh 或保存完整环境设置，最终提交包按相同设置复验。

使用 tools/cluster.py 和 config/cluster.local.json 检查环境、提交测试、恢复查询及取回日志。当前首次认证需要我在终端执行 python3 tools/connect.py 并保持登录，必要时 dlogin；随后你复用连接约一小时，不索取或保存密码。提交后记住 job ID，不因断线重复提交。验证调度器状态、退出码及所有预期用例的实际 PASS，不能只看进程成功。

在与父版本可比的环境中测试并登记结果，保留源码哈希、编译与运行条件、每个用例耗时、重复次数、实际参考库、原始日志和策略说明。record 使用本版本固定下载日志 .runs/题目/版本/benchmark.log。由 wrapper 独立执行三轮完整套件，record --repeats 3 指这三轮，不等于 TEST_RUNS；报告跨轮中位数和波动，并注明单轮值是否为程序内部平均值。失败、退化、无效与回退尝试也全部记录。

用 experiment.py compare 比较结果。只有正确性通过且同环境复测支持提升时，按仓库协作流程晋级；若共同基线已被别人更新，先同步再验证。未确认官方评分公式前，不把总耗时或 GFLOPS 写成官方分数。

你可以自主完成本地修改、Git 分支、SSH 测试、查询和记录，无需每轮向我确认。正式比赛平台提交由我处理。当前 setup/agent-workflow 分支只在本地，GitHub 账户仅有 READ 权限，不声称已推送。若网络或认证不可用，请完成不依赖连接的工作，保留可执行命令，准确指出未验证的步骤，不编造成绩。

最后给我简短汇报：本轮假设与改动、测试环境、逐用例结果与波动、是否晋级、当前共同基线、失败尝试记录位置，以及下一项最值得验证的假设。
```
